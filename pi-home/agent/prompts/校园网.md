请加载并使用 pc-repair 与 campus-network 两个技能，排查这台电脑的上网问题（校园 802.1X 认证环境）。

严格按 campus-network 技能里的顺序执行：
1. **只读诊断**：
   - 物理网卡状态（是否被禁用、是否 Disconnected）；
   - IP/网关/DNS（是否 169.254.x.x = DHCP 失败）；
   - **认证客户端**（锐捷 RJ Supplicant / 深澜 Srun / iNode / Dr.COM 的进程与服务状态）；
   - 代理（WinHTTP、IE、环境变量 http_proxy 等）；
   - 虚拟/VPN 网卡与**生效默认路由**（校园学生机常被加速器抢走默认路由）；
   - 近 7 天 IP 冲突事件（Tcpip 4198/4199）；
2. **三段连通性定位**：网关 → 外网 IP（223.5.5.5）→ 域名解析，据此判断是本地/认证问题还是 DNS/代理问题；
3. **需要修复时**：逐项说明风险，使用 fix.ps1 的 F01（刷新DNS）、F15（恢复自动获取IP/DNS，**必须先确认原本不是固定IP**）、F16（清理代理）、F17（启用被禁用网卡）、F20（上网故障急救组合动作）、F21（重启认证客户端服务），每一项都要我确认；
4. **红线**：不绕过 802.1X 认证、不做 MAC 欺骗、不擅自卸载/重装认证客户端、不改实验室机器的固定 IP、不删除虚拟网卡（只建议临时禁用）。若是多台机器同时故障，直接判断为网络侧问题并建议报修网管。

完成后把结论写进 reports\ 下最新目录的 ai_analysis.txt，并运行 `powershell -NoProfile -ExecutionPolicy Bypass -File core\ps\ticket.ps1` 生成维修工单。
