# 个人项目源码公开与签名准备

本轮交付是可审阅的本地源码准备结果，没有上传、推送、创建远程仓库或提交签名申请。维修、真实 AI、管理员提权和私人归档能力保持原样。

公开前请维护者确认根 LICENSE 的集体版权署名及原创代码/提示词授权，见 docs/LICENSING.md。自有代码按 MIT 准备，第三方代码与声明仍用原许可；尚无证据的来源问题如实待确认，不将未知代码归属给本项目。当前源码不捆绑尚未核实的大型运行时和工具 exe，未来分发完整便携包时再按 docs/DEPENDENCIES.md 补齐实际依赖来源与许可。

已知风险保留在 docs/SECURITY-REVIEW.md：确认覆盖、备份失败继续修改、跨机器报告关联等尚未修复。本次可作为明确标注风险的候选源码公开，不称为正式安全发布版；这些风险不在本轮展开重构或完整 VM 验证。原目录历史凭据是否曾公开仍需维护者确认，不能将候选清理当成旧凭据已撤销或旧 Git 历史已清理。

最短公开步骤（由维护者后续执行）：

1. 仅以本候选目录建立源码仓库，先本地暂存并审阅，勿从候选外原项目复制 `.git`、运行数据或配置。禁止强行添加被忽略的文件。README、LICENSE、隐私与签名政策应随源码公开。
2. 提交前检查暂存路径与差异，不含真实账户、Key、Token、私人配置、会话、日志、报告、备份和历史副本。沿用现有 `.gitignore`、`.gitattributes` 和发布清单；这些规则不替代对新增内容的审阅。
3. 创建本人控制的公开仓库，再推送已审阅提交。仓库简介可写“便携 Windows 诊断与维修工具，用户自备 AI 账户，MIT，候选版”。发布说明链接隐私与已知风险，不写已获 SignPath 签名。
4. 源码附件使用 Public 构建的新输出；不要直接压缩运行过的工作目录或私人现场部署。当前源码包可执行：

```powershell
powershell -NoProfile -File make_usb.ps1 -Target .\dist\public-source -SkipRuntime -NoKey -Quiet
```

输出必须是不存在的新目录。完整便携包的离线依赖清单另外提供，公开构建仍用干净默认配置。忽略和 export-ignore 的本地 config/auth/settings 不进入源码提交；使用者按模板或菜单自行配置。

修改公开源码后，先审阅变化，再将新增公开文件显式加入 release/approved-paths.json，执行 `python -B release/create_manifest.py` 更新 SHA256。本轮只是许可/文档改动，检查这些变化与哈希映射即可，沿用上一轮的语法与 22 项发布隔离结果，不重复执行维修或全套测试。若以后修改复制逻辑或配置处理，再运行对应发布隔离测试。

免费签名申请：补齐 docs/SIGNPATH-APPLICATION.md 的维护者、公开仓库与产物信息，审阅根 SIGNING_POLICY.md 草稿；再按 https://signpath.org/ 最新要求人工申请。当前脚本产物的支持范围、CI 平台与资格仍需确认，尚未获批或集成。签名只针对可追溯的自有产物，第三方保留原签名；不承诺签名能消除安全软件拦截。
